# Мониторинг курса EUR/USD

Сервис отслеживает курс EUR/USD и присылает уведомление в Telegram, когда
курс изменяется на 0.001 и более относительно последнего значения, по
которому уже было отправлено уведомление.

## Как это работает

```
cron-job.org (каждые 15 минут, Пн–Пт, 09:00–20:00 по времени Испании)
        │  HTTP POST
        ▼
GitHub Actions (repository_dispatch)
        │
        ▼
check_rate.py: получить курс → сравнить с last_alert → записать в лог → при необходимости отправить уведомление
```

- Источник курса — публичный JSON-эндпоинт Yahoo Finance
  (`https://query1.finance.yahoo.com/v8/finance/chart/EURUSD=X`). Он
  выбран вместо HTML-парсинга страницы котировки, так как отдаёт
  структурированные данные напрямую и не зависит от вёрстки сайта.
- Все временные метки — по времени Испании (Europe/Madrid, с
  автоматическим учётом перехода на зимнее/летнее время).
- История всех проверок и последнее отправленное оповещение хранятся в
  `rates_log.json`.

## 1. Создание Telegram-бота и получение chat id

1. В Telegram напишите **@BotFather**, отправьте `/newbot` и следуйте
   инструкциям. В конце вы получите **токен бота** — это и есть
   `TELEGRAM_BOT_TOKEN`.
2. Напишите вашему новому боту любое сообщение (например, «привет») —
   боты не могут писать первыми, это разрешает боту отправлять вам
   личные сообщения.
3. Узнайте свой **chat id** одним из способов:
   - Напишите боту **@userinfobot** — он пришлёт ваш `id` в ответ.
   - Либо откройте в браузере
     `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` после
     сообщения из шага 2 и найдите поле `"chat":{"id": ...}` в ответе.
4. Сохраните это число — это `TELEGRAM_CHAT_ID`.

## 2. Добавление секретов в GitHub

В репозитории: **Settings → Secrets and variables → Actions → New
repository secret**. Добавьте:

| Имя секрета            | Значение                              |
|-------------------------|----------------------------------------|
| `TELEGRAM_BOT_TOKEN`    | токен из @BotFather                    |
| `TELEGRAM_CHAT_ID`      | ваш personal chat id                   |

## 3. Токен для cron-job.org

cron-job.org должен уметь вызывать GitHub API, чтобы запускать workflow
(`POST /repos/{owner}/{repo}/dispatches`). Для этого нужен отдельный
GitHub-токен — он **не хранится в репозитории**, а вводится прямо в
настройках задания на cron-job.org.

Рекомендуемый вариант — **fine-grained personal access token**
(минимально необходимые права):

1. GitHub → **Settings → Developer settings → Personal access tokens →
   Fine-grained tokens → Generate new token**.
2. **Repository access** → **Only select repositories** → выбрать этот
   репозиторий.
3. **Permissions → Repository permissions → Contents** → **Read and
   write** (этого достаточно, чтобы вызывать `dispatches`; больше
   ничего не требуется).
4. Задайте срок действия токена и сохраните его — он показывается один
   раз.

Альтернатива — **classic PAT** со scope `repo` (для приватного
репозитория) или `public_repo` (если репозиторий публичный). Это даёт
более широкие права, чем нужно, поэтому fine-grained вариант
предпочтительнее.

## 4. Настройка задания на cron-job.org

Создайте новое задание (**Create cronjob**) со следующими параметрами:

- **URL**: `https://api.github.com/repos/<owner>/<repo>/dispatches`
  (замените `<owner>/<repo>` на владельца и имя репозитория)
- **Метод (Request method)**: `POST`
- **Заголовки (Headers)**:
  ```
  Authorization: Bearer <ВАШ_ТОКЕН_ИЗ_ШАГА_3>
  Accept: application/vnd.github+json
  Content-Type: application/json
  ```
- **Тело запроса (Body)**:
  ```json
  {"event_type": "check-rate"}
  ```
- **Расписание (Schedule)**:
  - Дни недели: понедельник – пятница
  - Время: с 09:00 до 20:00
  - Периодичность: каждые 15 минут
  - **Часовой пояс задания**: `Europe/Madrid` — cron-job.org позволяет
    выбрать таймзону для задания в настройках расписания; выбирайте
    именно её, а не UTC, чтобы переход на летнее/зимнее время
    учитывался автоматически и расписание не «съезжало» на час дважды
    в год.

После сохранения cron-job.org будет каждые 15 минут в указанном окне
отправлять `repository_dispatch` событие `check-rate`, которое запускает
workflow `.github/workflows/check-rate.yml`.

## 5. Ручное тестирование

### Проверка самого workflow

1. Откройте вкладку **Actions** в репозитории → workflow **Check
   EUR/USD rate**.
2. Нажмите **Run workflow** (это триггер `workflow_dispatch`).
3. Дождитесь завершения и проверьте логи шага «Run rate check» — там
   будет видно, найден ли курс и было ли отправлено уведомление.

### Проверка логики оповещения (порог 0.001)

По выходным рынок закрыт, и курс не меняется, поэтому ветку
«изменение ≥ 0.001» нужно проверять искусственно:

1. Откройте `rates_log.json` и вручную измените `last_alert.rate` так,
   чтобы разница с текущим реальным курсом EUR/USD была ≥ 0.001
   (например, если сейчас курс около 1.1450, поставьте `1.1400`).
2. Закоммитьте это изменение (пометьте коммит явно, например
   `test: искусственно сдвинуть last_alert.rate для проверки алерта`, —
   чтобы не спутать с реальными данными).
3. Запустите workflow вручную (**Actions → Run workflow**).
4. Убедитесь, что пришло сообщение в Telegram в формате:
   ```
   EUR/USD UP: изменение 0.0038
   Было: 1.1400 (22:40)
   Стало: 1.1438 (22:43)
   Источник: Yahoo Finance
   ```
5. Убедитесь, что `rates_log.json` обновился: `last_alert` теперь
   содержит новый курс, а в `history` появилась запись с
   `"alert_sent": true`.
6. Если тестовое значение `last_alert.rate` из шага 1 больше не нужно —
   оно уже будет перезаписано реальным курсом после срабатывания
   алерта в шаге 4–5; никаких дополнительных откатов не требуется.

## Формат данных

- Курс: 4 знака после запятой, например `1.1446`.
- Метки времени: `ДД.ММ.ГГГГ ЧЧ:ММ:СС` в логе, `ЧЧ:ММ` в сообщениях —
  всегда по времени Испании (Europe/Madrid).
- Порог срабатывания: абсолютная разница `0.001`.

## Файл rates_log.json

```json
{
  "last_alert": {
    "rate": 1.1400,
    "timestamp": "17.07.2026 22:40:00"
  },
  "history": [
    {"rate": 1.1400, "timestamp": "17.07.2026 22:40:00", "alert_sent": true},
    {"rate": 1.1412, "timestamp": "17.07.2026 22:55:00", "alert_sent": false}
  ]
}
```

При самом первом запуске (когда `last_alert` ещё `null`) сервис
сохраняет текущий курс как точку отсчёта и не отправляет уведомление —
отправлять «алерт» не с чем сравнивать было бы бессмысленно.
